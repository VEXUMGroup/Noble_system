# 議事録：営業プロセスの6月本格運用に向けたアプリ実装方針

- **日時**：2026-04-23（木）10:02 JST 〜 約45分
- **会議体**：noble 商談管理システム 要件すり合わせMTG
- **出席者（想定）**：田中貴久（vexum／noble常駐）、柏原さん（Noble）、川崎さん（Noble）、ほか
- **情報源**：Gemini によるメモ（[Google Docs](https://docs.google.com/document/d/18jNuQ4ZqQCUJJPRgh8L6TvNkNWJKMCUbQn51-mD56qE/edit?tab=t.53bu5z7sg0aj)）

## 1. 会議サマリー

営業プロセスの効率化と6月の本格運用に向けたアプリ実装方針を策定し、契約書送付機能の導入を決定した。

- **営業プロセスと運用計画**：6月の本格運用を目指し、5月中旬までにテスト環境を構築。商談情報の一元管理により既存スプシの二重管理を解消。
- **機能改善と契約実装**：商談一覧画面のステータス管理・支払い情報入力項目を整備。ボタン一つで契約書送付依頼ができる機能の実装を決定。
- **モバイル対応と優先順位**：営業担当者が外出先でも使えるよう、レスポンシブ対応を最優先。段階的に機能を拡充する方針。

---

## 2. 決定事項・主要ポイント

### 2-1. 運用ロードマップ
- **6月**：営業部一斉の本格運用開始（最優先）
- **5月中旬**：営業担当者が触れるテスト環境を構築／テスト運用スタート
- **5月中旬〜6月**：2週間ごとに2回程度の修正サイクル
- 現在のスプシ二重管理を解消し、商談情報を**一元管理**する方向で合意

### 2-2. 商談一覧画面
- カレンダー情報から**自動反映**を基本とし、取れない項目（経路など）は**手入力**で対応
- Lステップからの API 連携は「調査中」→ 取れない場合は従来通り手入力でカバー
- ステータス（検討／対象外／成約 等）変更時に**理由を選択・入力できる項目**を追加
  - 年齢対象外／時期対象外などはプルダウン
  - それ以外は自由記述コメント
- 検討時は**追いタイミングを日付**で入力可能に
- ステータスごとに商談一覧でまとめて表示できるUIを想定

### 2-3. 成約詳細入力
- プラン（10／12／18／24／30ヶ月／その他＋コメント）
- 支払いプラン（一括／分割／完全成功）
- 支払い方法（銀行振込／クレジットカード）※複数選択可の方向
- 支払い企業
- 対象予定日（日付／チェアクリアなど文字列どちらも許容）
- **イレギュラー記載**（支払い回数、入金方の分岐、カードの変更等を自由記述）
- **メモ**（自由記述）
- これらの入力項目は**マスター管理**で柔軟に変更可能な仕様へ（将来的に管理側で自由にプルダウン／カレンダー等の入力形式を変更できるようにする）

### 2-4. 契約書送付依頼フロー
- 成約情報入力後の**承認画面**で、カレンダー情報の下に「契約金額・プラン・対象予定日・メモ」を表示
- **必須項目**：対象予定日、電話番号
- **ボタン一つで契約書送付依頼**を実行できる機能を実装
- 送付主体の区別（例：味噌歩か／営業側かのフラグ）を入力欄に追加

### 2-5. 人材提案管理
- 人材提案（対象紹介／カヒリ）は成約・検討・対象外のいずれでも発生し得る
- → **面談済みの後、ステータス選択前の段階**で「人材提案のプルダウン」を選択できる導線を用意
- 検討／対象外の場合も人材提案情報を入力できるよう設計

### 2-6. 締結フェーズ
- 現状「郵便番号含め4項目」→ **「住所」と「締結日」の2項目に集約**（前回の柏原さんFB反映）

### 2-7. 支払い管理
- 事務側の機能。柏原さんがスプシで運用中の内容をシステム化
- 一部入金→完了まで管理。完全実装は営業の次フェーズ
- 代理店コミッション管理は後回し

### 2-8. モバイル対応
- **レスポンシブ対応を最優先**
- スマホ（全員同一機種想定で大きな差異なし）で快適に動作するUI設計
- iPadなど使う場合は別途検討
- 5月中旬の配布時点で「携帯で使えるアプリ」として提供

## 3. 優先順位（合意）

| 優先度 | 対象 | 内容 |
|---|---|---|
| 1 | 営業フェーズ | 制約詳細入力画面の項目追加（支払い自由記述・イレギュラー・メモ・契約書送付ボタン・人材プルダウン）＋ スマホ実装 |
| 2 | 流乳（支払い）マスター | 管理側でプルダウン等を編集可能にするマスター機能 |
| 3 | 支払い管理 | 事務側の入金管理機能 |
| 4 | 代理店 | 代理店・コミッション関連機能 |
| — | スプシ一元管理 | 上記が整ってから。現時点の最優先には入れない |

---

## 4. リスク・懸念

- **Lステップ API の取得範囲が未検証**。カレンダー情報・顧客情報をどこまで引けるかで、営業フェーズの工数に直結する最大の不確実性
  - 最悪の場合：カレンダー情報コピー→牛乳（？）全手打ち で運用カバー
- マスター編集機能（管理側でプルダウン等を自由にカスタマイズできる仕様）は工数的に時間がかかる見込み
- 「一元管理」は二重管理を解消できないと意味がないため、他システムとの統合戦略が整うまで優先度を上げない

---

## 5. ネクストアクション（田中）

- 営業フェーズの項目追加実装
  - 制約詳細入力画面：支払い自由記述／イレギュラー／メモ／契約書送付ボタン／人材プルダウン
  - 面談済み後・ステータス選択前の人材提案プルダウン導線
  - 締結フェーズを「住所・締結日」の2項目に修正
- スマホ（レスポンシブ）対応の実装
- Lステップ API 調査（**最優先／最大リスク**）
- 5月中旬：テスト環境を営業に配布
- 6月：一斉本格運用スタート
