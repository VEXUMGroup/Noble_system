## ✅ 決定事項まとめ

| # | 論点 | 決定内容 |
|---|---|---|
| 1 | マスター対象範囲 | 流入経路・代理店・成約プラン・担当者の4つ。ステータスはハードコードのまま。 |
| 2 | 担当者とGoogle認証 | 管理者が先にメールアドレスを登録 → Googleログイン時に照合・紐付け。未登録は弾く。 |
| 3 | 削除方針 | ソフト削除（`is_active` フラグ）で統一。既存商談の表示はそのまま維持。 |
| 4 | ID採番 | システムが自動採番（UUID）。コードの手入力なし。 |
| 5 | 表示順管理 | 数値入力で `sort_order` を管理。ドラッグ＆ドロップは将来対応。 |
| 6 | 権限管理 | 5月中旬テストまでは全員編集可（権限チェックなし）。`is_admin` は6月本番前に追加。 |
| 7 | 将来の拡張 | 入力形式（型）変更機能は今回スコープ外。名称・表示順・有効無効のCRUDのみ。 |

## DBスキーマ（確定版）

```sql
-- 流入経路マスター
CREATE TABLE master_sources (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  sort_order INT DEFAULT 0,
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- 代理店マスター
CREATE TABLE master_agencies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  contact TEXT,
  sort_order INT DEFAULT 0,
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- 成約プランマスター
CREATE TABLE master_plans (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  price INT,
  sort_order INT DEFAULT 0,
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- 担当者マスター
CREATE TABLE master_users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL,  -- Google OAuthのメールアドレスで照合
  is_admin BOOLEAN DEFAULT false,
  is_active BOOLEAN DEFAULT true,
  sort_order INT DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

> ⚠️ 既存 `deals` テーブルの外部キー（`source_id`, `agency_id` 等）がある場合、UUID に合わせて更新が必要。

## 実装ステップ（順番確定）

### Step 1 — DBマイグレーション
- 上記4テーブルを `supabase/migrations/002_master_tables.sql` として作成
- 既存のモックデータを初期データとしてINSERT

### Step 2 — Supabase CRUD関数の追加
- `src/lib/supabase.ts` にマスター系の取得・追加・更新・無効化関数を追加
- 取得は `is_active = true` のみ返す（無効データは除外）

### Step 3 — `master/page.tsx` の実データ化
- `mockSources` / `mockPlans` / `mockAgencies` → Supabaseから取得に切り替え
- 担当者タブを追加
- 追加・編集・無効化（削除）の操作を実装
- 表示順（数値入力）の編集対応

### Step 4 — 既存画面のプルダウンをマスターデータから取得
- 商談入力画面の流入経路・代理店・プランのプルダウンをDBから動的取得に変更
