# 2026-07-16 通知センター軽設計

## 前提
- 本設計は、既存のダッシュボード右側「通知」欄を本実装へ置き換えつつ、全画面の通知センターを追加するための軽設計とする。
- ユーザー記載の「画面ひたり上」は文脈上「画面左上」を指すものとして解釈する。
- 現時点では新機能の設計のみを定義し、`SPEC.md` は実装と確認完了後に更新する。

## 目的
- ダッシュボード通知欄を、固定モック表示ではなく実通知の概要表示にする。
- 過去通知を一覧・確認できる通知センター画面を追加する。
- 通知から関連商談へ安全に遷移できるようにする。
- Web Push 通知をタップした際も、通知ごとの遷移先へ移動できるようにする。

## 画面イメージ

### 1. ダッシュボード通知欄
- 右側の通知欄の見た目は大きく変えない。
- 表示内容は「直近の通知サマリー数件」とする。
- 各通知行をクリックすると通知詳細ページへ遷移できるようにする。
- 通知欄ヘッダーにも「一覧を見る」導線を置く。

### 2. 通知センター
- 新規画面 `/notifications` を追加する。
- 時系列で通知を一覧表示する。
- 未読・既読が視覚的に分かるようにする。
- 通知種別、作成日時、概要文を表示する。
- 通知を押すと、必ず通知詳細ページを開く。
- 通知詳細ページから関連商談へ遷移できるようにする。

### 3. ヘッダー左上ボタン
- 各画面の左上付近に、通知センターへ遷移するボタンを追加する。
- 既存ヘッダー構造を踏まえ、モバイルのメニューボタン付近またはその並びに配置する。
- アイコンのみの小型円形ボタンとし、通知センターだと分かるベル系アイコンを使う。
- 未読件数がある場合は小さなバッジ表示を検討する。

### 4. サイドバー導線
- 左サイドバーにも、文字なしの小さな円形通知ボタンを追加する。
- クリックで `/notifications` に遷移する。
- 他メニューと視覚衝突しない位置に置く。

## 通知データの考え方

### 現状
- ダッシュボード通知欄は `mockNotifications` を直接表示している。
- 実際の通知ログは `notifications` テーブルに保存されている。
- 既存テーブル項目は `user_id`, `deal_id`, `type`, `message`, `is_read`, `created_at` が中心。

### 今回必要になるもの
- 通知一覧表示に必要な最小情報
  - 通知ID
  - 通知種別
  - 本文
  - 関連商談ID
  - 既読/未読
  - 作成日時
- Push タップ時や画面遷移を安定させるため、通知ごとの遷移先情報を持たせる案を検討する。
  - 候補: `target_path`
  - 代替案: `deal_id` から画面側で `/deals/{id}` を組み立てる

## 初期対象通知
- まずは既に通知基盤があるものから通知センター表示対象にする。
- 初期対象候補
  - 支払期日3日前の未入金通知
  - 検討管理の次回アクション通知
  - 退職日アラート
- 将来的に契約完了通知や事務向け通知も追加できる構成にする。

## 遷移設計

### 1. ダッシュボードから
- 通知サマリー行クリック
  - `/notifications/{id}` の通知詳細ページへ遷移する

### 2. 通知センターから
- 通知行クリックで `/notifications/{id}` の通知詳細ページを開く
- 通知詳細から「関連商談を開く」操作で `/deals/{dealId}` へ遷移する

### 3. Web Push から
- 通知 payload に通知詳細ページの URL を含める
- service worker の `notificationclick` で、その URL を優先して開く
- フォールバックは `/notifications` とする

## 既読制御の方針
- 通知詳細ページを開いた瞬間に既読にする。
- 一覧表示しただけでは既読にしない。
- 将来的に一括既読や手動既読ボタンを追加できるようにする。

## 実装ステップ案

### ステップ 1. 設計確定
- 通知詳細ページを必ず挟む前提で URL 設計を確定する
- 必要な DB カラム追加有無を確定する
- 初期対象通知種別を確定する

### ステップ 2. データ取得層
- `notifications` テーブルからログインユーザー向け通知を取得する処理を追加する
- 既読更新処理を追加する
- 必要なら通知作成時に遷移先情報を保存する

### ステップ 3. UI 実装
- ダッシュボード通知欄を実データ化
- `/notifications` 画面を追加
- ヘッダー左上の通知センターボタンを追加
- サイドバーの円形通知ボタンを追加

### ステップ 4. Push 連携
- 通知 payload に遷移先を含める
- service worker のクリック遷移先を通知単位に変更する

### ステップ 5. 検証
- ダッシュボードから通知センターへ遷移できること
- 通知センターから関連商談へ遷移できること
- 未読/既読表示が崩れないこと
- Push 通知をタップした際に期待画面へ遷移すること
- 権限不足、通知データなし、対象商談なしでも誤作動しないこと

## 今の想定での注意点
- `notifications` テーブルに `title` や `target_path` が必要かは実装前に確認する。
- 既存の通知 API は支払通知中心なので、他通知種別との共通化方針を先に軽くそろえる。
- 通知センターの UX は、最初から作り込み過ぎず、一覧と安全な遷移を優先する。
